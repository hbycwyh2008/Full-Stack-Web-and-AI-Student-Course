# Lesson 11: Final Polish, Quiz, and Submit

## Lesson Goal

By the end of this lesson, each student should be able to:

1. Complete one polished mini project — login page, profile card, or landing hero section.
2. Use Flexbox intentionally in at least two places.
3. Write a project `README.md` in their own words.
4. Complete the Coursera **HTML and CSS Crash Course Quiz** (or finish it as homework if your teacher assigns a deadline).
5. Submit final unit evidence listed below.

## Required Resource

Open only the resource named in `Individual Learning`. The quiz is about 30 minutes — start it in class only if time remains after project polish.

## What to Focus On

**Today's pattern:** final project polish, Coursera quiz, module completion, and unit submission. Flexbox build happened in [Lesson 10](lesson-04-flexbox-mini-project.md).

## Guided Practice (55–75 min)

1. Finish your chosen mini project.
2. Use Flexbox in at least two places.
3. Add or update `README.md`:

```md
# Web Basics Mini Project

## Project Type
Login page / Profile card / Landing hero

## What This Page Does
One sentence in your own words.

## What I Learned
- Lesson 1 idea
- CSS idea
- Flexbox idea
```

4. Test desktop and narrow browser widths.
5. Complete the **HTML and CSS Crash Course Quiz** on Coursera.
6. Watch item 31 after submitting the quiz.
7. Commit with message: `Complete web basics mini project`.

## Exit Check (75–85 min)

Close Coursera after the quiz. Improve one visual detail and explain which Flexbox parent controls which children.

**Final project rubric — self-check before submission:**

| Criterion | Strong | Developing | Starting |
|---|---|---|---|
| HTML structure | Semantic tags, valid structure, working links and meaningful text | Mostly valid; minor gaps | Broken or missing structure |
| CSS organization | External stylesheet; clear selectors | Works but messy | Inline styles or disorganized |
| Visual layout | Centered, readable, Flexbox used intentionally | Works but uneven | Hard to read or broken |
| Code readability | Indented, logical class names | Mostly readable | Difficult to follow |
| GitHub evidence | Screenshots, commits, README submitted | Most evidence present | Missing key evidence |
| Reflection quality | Specific about build, learnings, and fixes | General but honest | Vague or missing |

## Evidence to Submit (85–90 min)

1. Screenshot or preview of your finished mini project
2. GitHub folder link to `web-basics-project/`
3. Commit history showing meaningful work across the unit
4. Coursera quiz completion screenshot (if your teacher requires it)
5. Completed final project rubric self-check
6. One sentence: "This unit taught me ___; my page demonstrates it by ___."
