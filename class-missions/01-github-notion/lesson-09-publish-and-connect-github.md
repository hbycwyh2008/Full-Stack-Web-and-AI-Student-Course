# Lesson 2: Publish and Connect GitHub

## Lesson Goal

Publish your Notion portfolio as a public website and connect it back to your GitHub repository so your showcase and evidence support each other.

By the end of this lesson, someone should be able to open your Notion portfolio, understand your Phase 0 learning, and click through to your GitHub evidence.

## Required Resource

Open only the resource named in `Individual Learning`. If the resource is longer than 15 minutes, complete the assigned section in class and finish the rest as homework if your teacher assigns it.

## Success Criteria

You are successful if:

1. Your Notion portfolio link opens correctly.
2. Your portfolio includes required sections from Lesson 1 plus at least two supporting sections.
3. Your Notion page links to your GitHub repository.
4. Your GitHub `README.md` links back to your Notion portfolio.
5. Your GitHub commit history shows a meaningful README update commit.
6. You can explain why this course uses both Notion and GitHub.

## Common Problems

| Problem | Try first |
|---|---|
| My public link does not open | Check Notion sharing or publishing settings. |
| The link opens editing mode | Copy the public view link, not your private workspace URL. |
| I cannot publish because of school settings | Submit a teacher-viewable link and screenshot. |
| My GitHub README link is broken | Paste the full Notion URL and test it after committing. |
| I only submitted Notion | Also update GitHub; the two-way connection is required. |

## Fast Track / Support Track

Fast track:

If most students complete this lesson in about 45 minutes, use the rest of the 90-minute block as a Phase 1 portfolio audit.

Students should check that they have:

1. A working Notion portfolio link.
2. A working GitHub repo link inside Notion.
3. A working Notion link inside GitHub `README.md`.
4. At least one Phase 0 reflection written in their own words.
5. No private personal information published accidentally.

If students are missing evidence, they should fix the evidence before moving into Phase 2.

Support track:

- Complete the smallest working version first.
- Ask for a hint after you can show what you tried.
- Submit honest evidence of progress if the full mission is not finished.
